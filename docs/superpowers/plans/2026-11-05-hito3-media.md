# master check · Hito 3 · Imagen, vídeo, MP3 y ADM — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que master check entregue también portada (JPG+PNG 3000×3000 sRGB), Spotify Canvas, vídeo de YouTube con imagen fija, motion artwork de Apple (opcional) y MP3 320, aceptando material propio arrastrado sobre cada ficha y conformándolo a la norma de cada plataforma; validación Apple Digital Masters en Mac; y cerrar las 14 mejoras de la revisión final del hito 2.

**Architecture:** Un **sidecar ffmpeg LGPL propio** (construido en CI desde fuente con `--disable-gpl --disable-nonfree --disable-everything` + solo lo necesario: demuxers/decoders de imagen y audio comunes, `aac` nativo, `libmp3lame`, `h264_videotoolbox` en macOS y `h264_mf` en Windows, muxer mp4 con faststart; un binario por target, firmado en hito 4) invocado por el motor como proceso aparte (`Command`), nunca enlazado. Portadas con el crate `image` (+ conversión a sRGB). El motor construye las líneas de comando de forma pura y testeable (golden args) y las ejecuta solo si el sidecar existe; en CI existe. Se elimina el `lame` CLI: el MP3 sale del mismo ffmpeg. Spike: `docs/investigacion/spike-video-hito3.md`.

**Tech Stack:** Rust; crates `image` 0.25 (MIT/Apache), `kamadak-exif` (BSD) para orientación, `moxcms` o `lcms2` para ICC→sRGB (verificar licencia; si no hay opción limpia, v1 asume sRGB y avisa); ffmpeg 7.x LGPL compilado en CI (macOS: clang + VideoToolbox; Windows: MSYS2/mingw-w64 + Media Foundation); Tauri `bundle.externalBin` con sufijo `-$TARGET_TRIPLE`; `ffprobe` del mismo build para tests de aceptación.

**Spec:** `docs/superpowers/specs/2026-11-05-master-out-design.md` §4, §5 (vídeo, portada, ADM), adendas 15:49 (fichas arrastrables) y 17:50; `docs/investigacion/spike-video-hito3.md` (normas confirmadas: Canvas 9:16, alto 720–1080, 3–8 s, MP4/JPG; Apple motion 3840×3840 y 2048×2732, 8–35 s, 23,976–30 fps, 45–100 Mbps, sin audio, Rec.709/sRGB; YouTube faststart, sin edit lists, GOP cerrado = fps/2, 2 B-frames, CABAC, AAC-LC 48 kHz 384 kbps); `docs/superpowers/reviews/hito2/final-review.md` (lista "Hito 3").

## Global Constraints

- Sin GPL ni "nonfree" en el bundle; openh264 descartado (la licencia de Cisco exige descarga separada). LGPL: el sidecar es un ejecutable aparte; junto al binario se publican (en el mismo servidor de descarga) el tarball de fuentes exacto, `configure_line.txt` y las licencias; aviso LGPL en "Acerca de". Pendiente de consulta legal antes de vender: patentes H.264/AAC (se usan codificadores del sistema para H.264) y estático vs dinámico.
- El audio del máster nunca cambia de nivel; el vídeo de YouTube usa el máster remuestreado a 48 kHz (dither por el plan) codificado a AAC-LC 384 kbps.
- Contrato de nombres §4 (es/en) para los nuevos archivos: `[Portada]/[Cover] 3000x3000.jpg/.png`, `[Canvas] 1080x1920.mp4`, `[YouTube] 1080p.mp4`, `[Apple Motion] 3840x3840.mp4` y `[Apple Motion] 2048x2732.mp4` (en `02 Apple Music/`).
- Todo texto visible por i18n; marca `nortia-brand`; nada de logos de terceros salvo activos oficiales aprobados (T8).
- Cada ficha de imagen/vídeo acepta material propio; si no hay material, se fabrica desde la portada; si no hay portada, la ficha se deshabilita con motivo (`reason.no_cover`).
- Tests: líneas de comando golden (puras); aceptación con ffprobe en CI (duración, tamaño, códecs, fps, faststart `moov` antes de `mdat`, sin audio donde toca); nunca se debilita un test para pasar.

## Review Focus

1. Imagen no cuadrada o pequeña (p. ej. 1500×1000 JPG con EXIF girada): se recorta centrada, se orienta, se avisa de upscaling, nunca se deforma. → T2 tests `conform_image_crops_center_and_warns_upscale`, `respects_exif_orientation`.
2. Vídeo de usuario para Canvas de 20 s horizontal 4K: recorte 9:16 centrado, 8 s máximo, sin audio, ≤ 1080 de alto. → T3 `canvas_from_user_video_is_conformed`.
3. Sidecar ausente o roto (ffmpeg borrado, sin permisos): las fichas de vídeo y MP3 se deshabilitan con motivo claro; el resto exporta. → T4 `missing_sidecar_disables_media_jobs_only`.
4. Windows N (sin Media Foundation) o VideoToolbox no disponible: error limpio `err.encoder_unavailable` por job, sin abortar la entrega. → T3 `encoder_failure_is_per_job`.
5. Portada con perfil de color no sRGB (Adobe RGB): se convierte o se avisa; nunca se escribe con perfil incrustado distinto de sRGB. → T2 `non_srgb_profile_is_converted_or_flagged`.

### Task 1: Sidecar ffmpeg LGPL construido en CI (macOS universal, Windows x64) con tests de aceptación

**Files:** Create `tools/ffmpeg/build-macos.sh`, `tools/ffmpeg/build-windows.sh`, `tools/ffmpeg/configure_line.txt`, `tools/ffmpeg/accept.sh`, `.github/workflows/ffmpeg-sidecar.yml`, `docs/legal/terceros.md`.

- Flags base (ambas plataformas): `--disable-gpl --disable-nonfree --disable-everything --disable-doc --disable-network --disable-debug --enable-small? (no: velocidad) --enable-protocol=file,pipe --enable-demuxer=wav,aiff,flac,mp3,mov,matroska,image2,png_pipe,mjpeg,webp_pipe --enable-decoder=pcm_s16le,pcm_s24le,pcm_s32le,pcm_f32le,flac,mp3,aac,h264,hevc,vp9,png,mjpeg,webp --enable-encoder=aac,libmp3lame,png,mjpeg,h264_videotoolbox|h264_mf --enable-muxer=mp4,mov,ipod,mp3,image2 --enable-filter=scale,crop,zoompan,gblur,boxblur,overlay,format,fps,setsar,trim,atrim,aresample,aformat,anull,null,color,loop,pad --enable-libmp3lame --enable-videotoolbox (mac) | --enable-mediafoundation (win)`; `--extra-ldflags` estáticos para libmp3lame.
- macOS: compilar arm64 y x86_64 por separado y unir con `lipo` → `ffmpeg-universal-apple-darwin` y `ffprobe-…`; `MACOSX_DEPLOYMENT_TARGET=14.0`. Windows: MSYS2 `mingw-w64-x86_64` toolchain, `--target-os=mingw32`, estático; `ffmpeg-x86_64-pc-windows-msvc.exe`.
- `accept.sh`: con el binario recién hecho, generar un WAV sintético y una PNG, y producir: canvas 1080×1920 6 s sin audio, youtube 1080p con AAC 384k 48k y `-movflags +faststart`, mp3 320 CBR; comprobar con ffprobe JSON: códecs (`h264`, `aac`, `mp3`), `profile` High, fps, tamaño, `nb_streams`, duración ±0,1 s, y que `moov` precede a `mdat` (leer los 4 primeros átomos). Falla el job si algo no cuadra.
- Artefactos: `ffmpeg-sidecar-<os>` con binarios, `SHA256SUMS`, `configure_line.txt`, `ffmpeg-<ver>.tar.xz` fuente y `LICENSE.LGPLv2.1`, `lame-<ver>.tar.gz` + `LICENSE`. El workflow se ejecuta por `workflow_dispatch` y cuando cambie `tools/ffmpeg/**`; publica también un *release* `ffmpeg-sidecar-v<ver>-<hash>` para que `app-build.yml` lo descargue (no recompilar ffmpeg en cada build de la app).
- `docs/legal/terceros.md`: tabla de componentes (ffmpeg LGPL 2.1+, LAME LGPL 2, flac-codec MIT/Apache, ebur128 MIT, rubato MIT, image MIT/Apache, Tauri Apache/MIT, Hanken Grotesk OFL), obligaciones y texto para "Acerca de"; nota de consulta legal pendiente (patentes H.264/AAC, LGPL estático).

### Task 3: Vídeo: Canvas, YouTube y Apple motion con el sidecar (args golden + ejecución)

**Interfaces:**
```rust
pub enum VideoSource { FromCover(PathBuf), UserMedia(PathBuf /* imagen o vídeo */) }
pub struct CanvasSpec { pub width: u32 /*1080*/, pub height: u32 /*1920*/, pub seconds: f32 /*6.0; user video: min(len, 8.0), ≥3.0 else loop*/ , pub fps: u32 /*30*/ }
pub struct YoutubeSpec { pub width: u32 /*1920*/, pub height: u32 /*1080*/, pub fps: u32 /*30*/, pub video_kbps: u32 /*8000*/, pub audio_kbps: u32 /*384*/, pub audio_rate: u32 /*48000*/ }
pub struct AppleMotionSpec { pub square: bool /* 3840×3840 | 2048×2732 */, pub seconds: f32 /*10*/, pub fps: u32 /*30*/, pub mbps: u32 /*60*/ }
pub fn build_canvas_args(src: &VideoSource, info: Option<&MediaInfo>, spec: &CanvasSpec, out: &Path, platform: Platform) -> Vec<String>
pub fn build_youtube_args(src: &VideoSource, master_wav_48k: &Path, spec: &YoutubeSpec, out: &Path, platform: Platform) -> Vec<String>
pub fn build_apple_motion_args(src: &VideoSource, spec: &AppleMotionSpec, out: &Path, platform: Platform) -> Vec<String>
pub fn run_ffmpeg(sidecar: &SidecarPaths, args: &[String], cancel: &dyn Fn() -> bool) -> Result<(), AudioError>  // mata el proceso al cancelar; stderr capturado → err.encoder_unavailable | err.ffmpeg_failed(detail)
pub fn probe(sidecar: &SidecarPaths, path: &Path) -> Result<MediaInfo, AudioError>
```
Filtros: Canvas desde portada = `zoompan` lento (1,0→1,08 en N frames) sobre recorte 9:16 centrado, `-an`; desde vídeo = `crop` 9:16 centrado + `scale` a alto ≤ 1080 + `trim` 8 s (loop si < 3 s) + `-an`; YouTube = fondo `gblur` de la portada escalada a 1920×1080 + portada 1000×1000 centrada, `-r 30 -g 15 -bf 2 -pix_fmt yuv420p -profile:v high -b:v 8M -movflags +faststart`, audio `-c:a aac -b:a 384k -ar 48000`; Apple motion = zoom lento, `-b:v 60M`, `-an`, `-color_primaries bt709 -color_trc bt709 -colorspace bt709`. Codificador: `h264_videotoolbox` (mac, `-allow_sw 1`) / `h264_mf` (win); flags por plataforma documentados.
- [ ] Tests golden (puros, sin ffmpeg): `canvas_args_from_cover_golden`, `canvas_args_from_user_video_trims_to_8s`, `youtube_args_golden_mac`/`_win`, `apple_motion_args_golden`. Tests de ejecución (`#[ignore]`-less pero saltan si no hay sidecar; en CI hay): `canvas_from_user_video_is_conformed` (entrada 4K horizontal 20 s sintética → ffprobe 1080×1920, ≤ 8,05 s, sin audio), `youtube_output_matches_spec` (h264 High, aac 384k 48k, moov antes de mdat, 30 fps), `encoder_failure_is_per_job` (encoder inexistente forzado → err.encoder_unavailable, no panic), `cancel_kills_ffmpeg` (< 2 s).
